# Calendar 执行收束

仅在写后读回不一致、长分页或多步清理时加载本文件。命令参数本身不确定时改读精确 leaf Help，不加载完整 `calendar.md`。

## 写入可能已提交

`readback_attendee_missing`、`readback_*_missing`、读回超时或失败不等于创建未发生。

1. 若结构化结果/错误中有 `eventId`，只协调该 ID：`event get`，需要时再 `attendee list`。
2. 若没有 ID，用原始 `title + start + end` 在窄时间窗唯一定位一次。
3. 唯一命中后把 ID 写入本轮台账并继续；零命中报告创建未证实；多命中停止消歧。
4. 禁止重放非幂等创建，禁止从同日列表选择别的事件，禁止把部分验证写成完整成功。

## 长分页

- 普通目标定位：1 个时间窗、最多 2 个关键词、最多 2 页。
- 用户明确要求完整遍历：优先 `--limit 100`。用户指定小页长时，在本地循环中仅累计 `eventId` 去重集合、匹配项、月度/状态计数和最终 `hasMore/nextCursor`；不要把每页完整事件送回模型。
- 每次检查游标非空、前进且未重复；缺失、停滞、循环、页数或耗时上限触发时标记未完成。
- 写任务在进入分页前就记录所有临时 ID；无论正常结束、超时还是分页失败，都先执行授权过的清理并逐个验证。
- 会议室可用性优先采用同一时段 `+room-find` / `room search` 的返回集合，不再逐间查询 busy；明确要求逐房间占用详情时按接口批量上限分批，失败只缩小批次一次。

## 多步资源台账

按用户验收顺序推进，始终保持这些绑定：

```text
created eventId -> title/start/end -> attendee IDs -> roomId
added aclId -> userId/privilege
uploaded fileId -> attached eventId
```

- 更新、换人、换房、恢复、删除只能引用同一行资源。
- 替换参会人：先确认旧/新 userId，再对同一事件移除旧人、添加新人、读回名单。
- 换会议室：先为新时段取得另一个真实可用 roomId，再从同一事件移除旧房、添加新房并读回；任一步失败时保留真实 partial 状态。
- 用户已在原请求明确要求最终清理时，不再二次询问；通过 Runtime confirmation gate 执行 `--yes`。
- `+suggest-time` 后核对候选实际分钟数；不足用户指定时长就报告无合格候选，不把短候选扩写成长时段。

## 立即收束条件

- `primary`/系统日历更新返回 `can't update system calendar`。
- 精确标题邀请在有限搜索后不存在。
- 用户限定范围内没有合法可用 `roomId`，或绑定返回业务拒绝。
- 必要参会人身份零命中/多候选。

触发后不要扩大范围、换无关资源或编造完成。若本轮已创建临时资源，先清理，再报告已完成、未完成与证据边界。

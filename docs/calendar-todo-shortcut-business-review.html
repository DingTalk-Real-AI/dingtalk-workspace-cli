Hidden failures fixed

这次真正修掉的“假成功”

问题来自真实 wire shape、分页和写后证据；mock 成功或空环境不能发现这些风险。

原问题错误风险修复与回归
缺失集合、错型集合或坏元素被投影为 []内部报错/协议漂移被误报为“无日程/无任务”。失败关闭 只有成功 envelope 内显式存在且类型正确的空数组才是合法空。
Calendar 事件列表真实字段是 result.events，稳定键是 id容错 projector 可能静默丢失真实事件。严格读取 wrapper，并将 id 规范化为 eventId。
Todo 列表真实字段是 todoCards，详情嵌套在 todoDetailModel错误 wrapper 使真实任务看似空结果或读回错对象。列表/详情分别建立严格 parser，详情必须绑定请求 taskId。
hasMore=true 时缺 cursor、重复 cursor 或只读首屏Top-N 被宣称为全量；空页可能提前结束。自动分页要求 token 前进；停滞、缺证据、超页上限均非零失败。
Calendar 删除后对象仍可读仅以“还能 get”判定删除失败，或仅凭 ack 判定成功。精确接受 absence 或同 eventId 的 cancelled/canceled/deleted tombstone，拒绝活动对象。
Todo 评论写回返回 result:{}从空 ack 伪造 commentId，或把请求正文当读回。完整读取写前/写后评论，要求唯一新增 ID 且正文精确一致。
Calendar attendee 真实项不含稳定 userId把 displayName 当 ID，发布无法兑现的身份合同。只投影 displayName、responseStatus、self；自身邀请通过当前 profile 与 self=true 绑定。
Calendar smart 写命令只看 ack 或 request echo创建、邀请、重排、取消的远端效果未知仍返回 0。create/update/invite 精确读回；cancel 验证 tombstone/absence；book 邀请失败时回滚并验证缺席。
Todo reminder 没有规则读回接口把 terminal success 伪装成 verified readback。结果固定标注 terminalReceipt=true、verified=false，报告公开边界。
live 清理最初遗漏子任务 ID能力全绿但测试数据仍残留。子任务进入反向清理账本；最终全量 marker 审计作为独立发布门，真实结果零残留。

Truthful execution

空结果与写成功的统一判定

这套合同同时落在 runtime、Result/Pagination 声明、负向回归和 live E2E，不只是报告规则。

读取 / 分页

1
外层与业务层都成功非零退出、success=false、空 body、malformed JSON 立即失败。
2
预期字段显式存在缺集合、null、非数组、坏 item 都不是合法空。
3
分页证据完整hasMore 必须配非空且前进的 token；上限未耗尽必须 incomplete/nonzero。
4
零命中与已知非空都验证只在空环境跑一次不能证明 projector 正确。

写入 / 读回

1
确认前零调用用户确认驱动 Runtime gate；存储示例不带 --yes。
2
明确终态与稳定 ID空 ack、无异常、request echo 均不是创建成功证据。
3
绑定同一对象读回ID、目标父级和关键字段必须与请求一致。
4
不可读回时降低声明明确 terminal-only / verified=false；不从截断列表或同名对象推断。

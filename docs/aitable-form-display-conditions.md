# 表单题目条件显隐

本功能通过既有表单字段更新入口配置条件，不新增表格字段，不修改固定隐藏或其他题目的配置。两个入口使用相同的规则校验和写后核验：

- `dws aitable form field update`
- `dws aitable +form-field-update`

## 参数与规则

两入口均接受 `--base-id`、`--table-id`、`--view-id`、`--field-id` 定位目标。更新项如下，至少提供一项：

| 参数 | 行为 |
| --- | --- |
| `--required true/false` | 修改必填；显式 false 必须保留 |
| `--field-description <文本>` | 修改填写说明；空字符串视为省略，纯空白文本报错 |
| `--display-condition <JSON>` | 整体替换目标题目的显示条件 |
| `--clear-display-condition=true` | 显式清除条件，保留必填和固定隐藏 |

未传入的更新项保持原值。设置与清除条件互斥；`clear=false` 不清除条件，单独传入不构成更新。条件不能用 null、空对象或空数组清除。

标准条件只支持一个 `and` 或 `or` 根节点，包含 1 至 20 个 `eq` 叶子；每个叶子的操作数依次为本表单单选来源字段 ID 和该字段的选项 ID。不使用展示名称，不支持嵌套分组：

```json
{
  "operator": "and",
  "operands": [
    {"operator": "eq", "operands": ["SOURCE_FIELD_ID", "OPTION_ID"]}
  ]
}
```

来源字段、选项、题目依赖和固定隐藏限制由服务端核对。客户端预检失败时返回参数错误、退出码 3，且不调用业务接口。

执行前读取当前入口的 compact Schema。可用 `--dry-run --format json` 查看参数预览；预览中的 `executed=false` 表示没有执行业务写入。原子入口保留既有字符串形式的 `required` 参数，Shortcut 保留布尔参数，两者都按明确的 true/false 构造请求。

原子入口的 `required` 延续旧输入语义：布尔文本解析前去除首尾空白；显式空字符串视为未传，此时仍须有其他有效更新。仅含空白的字符串仍是参数错误。

两个入口的 `field-description` 均将显式空字符串视为未传，仍须提供其他有效更新；这恢复了原子入口的旧兼容行为，不会用空字符串清除已有说明。非空文本保留首尾空白，纯空白文本仍是参数错误。

## 写后核验与恢复

仅在以下事实齐全时报告成功：

1. 回执确认成功且 `verificationStatus=verified`。
2. 回执的 Base、Table、View、Field 与请求一致，`actual.fieldId` 也匹配。
3. 实际必填和固定隐藏值类型正确；本次请求修改的必填、说明或条件与实际读回值一致。
4. 设置或清除条件时，`actual.displayConditionStatus=available`。

当状态为 `available`，条件为 null 或条件键缺失均表示已确认无规则。`unknown`、`unsupported` 或状态缺失时，null/缺键不能证明条件已清除。

多项更新不保证原子性。`pending`、`unknown`、目标不匹配、实际状态不完整或旧服务缺少核验证明时，返回 `partial_failure` 和退出码 7。保留原始回执及 `completedOperations`，按原目标只读核对；不要重放已完成部分、覆盖旧快照或用取消必填/永久隐藏替代条件显隐。

两个表单更新入口将结构化 `601`、`ORG_NOT_MATCH` 或 `ORG_DOC_TOKEN_MISMATCH` 识别为组织不匹配，保留上游错误码、trace 和原始错误，退出码 2。先核对当前 profile 与文档所属组织；不自动刷新凭据、切换账号、申请权限或重放写入。此处理限定在表单更新实现，不改变其他 MCP 工具的共享错误分类。

## 浏览器操作边界

优先使用当前已发布的接口能力；接口未就绪时应说明缺口，不编造菜单或新增题目。需要浏览器辅助时，必须以真实题目、按钮语义和当前视口定位操作目标；仅命中外层 iframe 或取得机械派发成功回执，不能证明点中了正确题目。操作后检查题目与字段集合，发现意外新增时停止并保留证据，不擅自删除用户已有字段。

## 验证范围

本仓的表单测试覆盖非法条件零调用、false 保留、两入口预览、成功/部分失败终态、清除的空值语义及组织拒绝。配套测评通过固定二进制和回环 MCP 验证真实 CLI 入口，另有仅发现精确 compact Schema 的 Agent 场景。

部署后仍需在获授权测试资源中执行设置、独立读回、清除、独立读回，并验证填写页在条件不满足时跳过、满足时显示且保持必填。记录实际部署版本和真实结果；单测、回环测试、套件装配或旧版本结果不能替代线上填写验收。
